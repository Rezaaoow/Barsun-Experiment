# اصلاح خطای حذف لینک‌های غیرفعال

گزارش واقعی Production نشان می‌دهد حذف تخصیص با قید `experiment_group_claim_requests_assignment_id_fkey` برخورد می‌کند. مسیر قبلی فقط consent، workflow progress و legacy timing را پاک می‌کرد؛ stage start receipts و time-event receipts نیز وابستگی FK دارند و باید پوشش داده شوند.

فقط شناسه‌های غیرفعال همان scope در یک تراکنش قفل و ثابت می‌شوند. رسیدهای اجرایی متعلق به همان لینک پیش از parent حذف می‌شوند. اشاره‌گر nullable درخواست تخصیص گروهی NULL می‌شود اما خود request ID و fingerprint حفظ می‌شود تا retry درخواست حذف‌شده 409 بدهد و شرکت‌کنندهٔ تازه ناخواسته نسازد. عملیات بسته‌های محدود ۲۰۰تایی دارد تا با سقف پارامتر SQLite و بار مدیریتی سازگار باشد. لینک‌های فعال و scope دیگر هدف نیستند.

اجرای پژوهشی، پاسخ‌های DD/UT/پرسشنامه، شرکت‌کننده، participation، ساعت قابل مشاهده و checkpointهای خام حذف نمی‌شوند. schema یا پروتکل پژوهش تغییر نمی‌کند. اصلاح کد به معنی اجرای حذف واقعی لینک‌های موجود نیست؛ کاربر بعد از انتشار می‌تواند از همان پنل حذف را انجام دهد.

آزمون باید خطای قبل را با وابستگی‌های واقعی گروه‌claim/start/time بازتولید، پاسخ‌ها و ساعت‌ها را قبل/بعد مقایسه و حفاظت scope/فعال‌ها و retry تخصیص گروهی را در SQLite و PostgreSQL بررسی کند. آزمون روی Staging فقط در مطالعهٔ مصنوعی مستقل و با scope دقیق همان مطالعه اجرا می‌شود؛ endpoint عمومی با scope تمام تست‌ها فراخوانی نمی‌شود.

بررسی محلی: مجموعهٔ کامل موجود با ۱۳۶ تست موفق شد و تست بستهٔ ۲۰۵لینکی نیز جدا موفق شد (۱۳۷ تست متمایز). PostgreSQL 17 و بررسی نهایی پاک‌نشدن داده‌های پژوهشی و tombstone تخصیص موفق‌اند؛ CI PostgreSQL 16 را جدا اجرا می‌کند. وضعیت انتشار واقعی با SHA در PR این اصلاح ثبت می‌شود.
