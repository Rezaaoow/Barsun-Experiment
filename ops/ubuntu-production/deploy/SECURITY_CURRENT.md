# Current targeted deployment security checks

New Production only. Separate key-only operator/repository identities, unprivileged app, local socket peer-authenticated PostgreSQL, immutable app code, loopback-only backend, trusted HTTPS and tested renewal are verified. App/public assets/admin authentication and a wrong-database startup rejection passed. Backups encrypt credentials/data and use root-only storage. This is not a comprehensive penetration test or a zero-risk claim.

The pinned baseline contains Starlette 0.46.2. The maintainer's CVE-2025-62727 advisory affects file Range handling in versions through 0.49.0: https://github.com/Kludex/starlette/security/advisories/GHSA-7f5h-v6xp-fcq8 . The experiment does not need byte-range downloads. Chosen targeted mitigation: Nginx strips Range/If-Range before every /dce/ upstream request and hides Accept-Ranges; backend remains loopback-only. A normal byte-range probe receives complete HTTP 200 asset bytes identical to the ordinary response. No large malicious/DoS payload was executed. This mitigates the documented public entry path without changing participant logic or dependency versions; the pinned dependency itself is not upgraded/patched by this measure. Do not remove this guard before separately validating a patched dependency stack.

No multipart/form parser package is installed in the production runtime and current routes accept JSON rather than request.form()/file uploads. This observation is not a blanket exemption for future routes/dependencies. Dependency changes are blocked by the release agent pending runtime validation. Keep follow-up dependency security review separate from claims of task/protocol correctness. Same-server backups remain vulnerable to disk/server loss and root compromise; external data backup and external alert delivery remain explicitly pending.
